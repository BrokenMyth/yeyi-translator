# 页译：Chrome / Edge 网页翻译插件

页译使用你自己的 **DeepSeek 或 OpenAI API Key** 翻译网页，支持原文与译文逐段对照，也支持用译文替换原文。

**当前版本：1.0.2。** 普通用户下载安装包即可使用，不需要安装 Node.js。

[下载安装包](https://github.com/T-miracle/yeyi-translator/releases/latest) · [查看全部版本](https://github.com/T-miracle/yeyi-translator/releases)

## 能做什么

| 功能             | 使用效果                                                  |
| ---------------- | --------------------------------------------------------- |
| 整页翻译         | 优先翻译当前屏幕，再继续翻译网页中其余已加载的文字        |
| 换行双语         | 每段原文下方显示译文，方便对照阅读                        |
| 替换原文         | 在原来的位置显示译文，尽量保留链接、加粗和页面排版        |
| 一键恢复原文     | 撤回插件的翻译改动，恢复阅读原文                          |
| 动态内容翻译     | 翻译开启后，继续处理滚动加载、展开或更新的文字            |
| 自动获取模型     | 填入 Key 后自动获取可用模型，也可以手动填写模型 ID        |
| 指定网站自动翻译 | 为常用网站开启自动翻译，其他网站保持手动                  |
| 两家服务分别配置 | DeepSeek 和 OpenAI 各自保存 Key、模型及 API 地址          |
| 兼容自定义接口   | 可以修改 API 地址和模型，连接兼容 Chat Completions 的服务 |

原文语言自动识别，默认译为简体中文。还可选择繁体中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语、阿拉伯语、意大利语、越南语和泰语。

## 第一步：下载安装包

1. 打开 [最新版本下载页面](https://github.com/T-miracle/yeyi-translator/releases/latest)。
2. 在页面的 **Assets（资源）** 中下载 `yeyi-translator-1.0.2.zip`。
3. 把 ZIP 解压到一个准备长期保留的文件夹。
4. 打开解压后的文件夹，确认里面能直接看到 **`manifest.json`**。

浏览器安装时选择这个文件夹。安装后请保留文件夹，因为浏览器会继续从这里读取插件文件。

GitHub 页面中的 **Source code（源码）** 压缩包用于开发，需要构建后才能加载。直接安装请使用上面的 `yeyi-translator-版本号.zip` 文件。

## 第二步：安装到浏览器

Chrome 和 Edge 使用同一个安装包，分别在各自的扩展管理页加载。

| 浏览器         | 在地址栏输入          |
| -------------- | --------------------- |
| Chrome         | `chrome://extensions` |
| Microsoft Edge | `edge://extensions`   |

进入对应页面后：

1. 打开 **开发者模式**。
2. 点击 **加载已解压的扩展程序**。Edge 中也可能显示为“加载解压缩的扩展”。
3. 选择第一步中包含 `manifest.json` 的文件夹。
4. 在浏览器的扩展菜单中找到“页译”，将它固定到工具栏，方便后续使用。

首次安装完成后，刷新一下准备翻译的网页。

## 第三步：填写 Key 并选择模型

点击工具栏中的“页译”，再点击设置按钮，进入插件设置页。

### 使用 DeepSeek

1. 在 [DeepSeek 平台](https://platform.deepseek.com/api_keys) 创建自己的 API Key。
2. 在插件设置的 **DeepSeek** 卡片中填写 Key。
3. 等待约 **0.75 秒**，插件会自动获取模型列表。
4. 从下拉框选择模型，例如 `deepseek-flash`。
5. 选择 **使用此服务**，可先点击 **测试连接**，最后点击 **保存设置**。

### 使用 OpenAI

1. 在 [OpenAI 平台](https://platform.openai.com/api-keys) 创建自己的 API Key。
2. 在插件设置的 **OpenAI** 卡片中填写 Key。
3. 等待自动获取模型，从列表选择支持文本对话的模型，例如 `gpt-4.1-mini`。
4. 选择 **使用此服务**，可先点击 **测试连接**，最后点击 **保存设置**。

可以同时保存两家服务的配置，再在工具栏弹窗中切换当前服务。插件不会自动替你切换到另一家服务。

### 默认地址和模型

| 服务     | 默认 API 地址（Base URL）   | 默认模型 ID      |
| -------- | --------------------------- | ---------------- |
| DeepSeek | `https://api.deepseek.com`  | `deepseek-flash` |
| OpenAI   | `https://api.openai.com/v1` | `gpt-4.1-mini`   |

以上默认值于 2026-10-15 核对。具体可用模型以你的账户权限和自动获取的结果为准。模型列表中可能包含不支持文本对话的模型，请按服务实际支持情况选择。

**模型展示名和模型 ID 可能不同。** 例如 `DeepSeek-V4.1-Flash` 是版本展示名，对应的 API ID 是 `deepseek-flash`。从下拉框选择时，插件会使用真实 ID 发起请求。已有输入只有在唯一匹配接口返回的名称或 ID 时，才会被改为真实 ID，并提示保存设置。

### 使用代理或其他兼容接口

1. 先把对应服务的 **Base URL** 改为服务方提供的 API 地址。
2. 再填写这个服务的 Key，等待自动获取模型。
3. 如果对方没有提供模型列表，选择或保留 **手动输入模型 ID**，填写服务方给出的 ID。
4. 测试连接并保存设置。

修改 Key 或地址后会重新自动获取模型；“重新获取”按钮可手动刷新。获取失败时，原来的模型配置会保留，你仍可手动填写。

获取模型只请求模型列表，不发送网页内容，也不会启动翻译。**测试连接会发送一条短文本；测试和网页翻译均可能产生 API 费用，费用由你配置的服务收取。**

## 如何翻译网页

1. 打开普通网页。
2. 点击浏览器工具栏中的“页译”，或者点击网页右下角的“页译”按钮。
3. 选择目标语言和翻译模式。
4. 点击 **翻译此页**。

### 两种翻译模式

- **换行双语**：原文保留，译文显示在每段原文下方。
- **替换原文**：原文位置显示译文，尽量保留链接、按钮行为及原有格式。

已有译文时，切换两种模式会直接复用译文，不重复请求 API。文字长度发生变化时，网页可能重新换行。

### 暂停、继续、恢复和重试

- **暂停翻译**：停止后续请求和新内容监测，保留已经完成的译文。
- **继续翻译**：复用当前页面中的结果，继续处理未完成部分。
- **恢复原文**：停止翻译并撤回插件改动。网站在翻译期间更新的文字会保留为网站的最新内容。
- **重试失败部分**：在工具栏弹窗中点击对应按钮，只重新请求失败的部分。

模型省略表情、标点或纯数字片段时，会保留原字符。批量译文缺项、格式错误或被截断时，会自动拆成更小的批次补译；缩小到单片段仍失败的内容可手动重试。

临时网络故障、限流和服务错误最多自动重试两次。Key 无效、额度不足或模型配置错误时，会提示原因并停止当前页面帧中的后续任务。

### 为常用网站开启自动翻译

在工具栏弹窗中打开 **此网站自动翻译**。之后重新进入这个网站时，就会自动开始翻译。

也可以在设置页的“自动翻译网站”中每行填写一个主机名，例如：

```text
docs.example.com
news.example.com
```

这里只精确匹配填写的主机名。`example.com` 不会同时包含 `docs.example.com`；需要分别添加。自动翻译会把页面文字发送到当前选择的 API 服务。

## 常见问题

### 找不到 `manifest.json`，或者浏览器提示无法加载

请先解压插件 ZIP，再选择包含 `manifest.json` 的文件夹。如果下载的是 GitHub 的源码压缩包，请按下文“从源码构建”操作，或重新下载 Release 中的插件安装包。

### 填入 Key 后没有获取到模型

检查 Key 是否有效、Base URL 是否正确、网络能否访问这个服务，再点击“重新获取”。部分兼容服务没有提供模型列表，可以手动填写模型 ID 后测试连接。

### 测试连接提示 HTTP 400

先看界面显示的具体服务错误和参数。常见原因包括模型 ID 填写错误，或者服务不支持当前请求参数。

对于 DeepSeek，请从自动获取的列表中选择模型 ID，例如 `deepseek-flash`，然后测试并保存。不要直接把版本展示名当作模型 ID。

### 提示 Key 无效、额度不足或请求过于频繁

- **Key 无效**：检查是否填错服务、Key 是否完整、是否已被撤销。
- **额度不足**：到对应服务平台查看可用额度或余额。
- **请求过于频繁**：稍后重试，或减少同时翻译的网页数量。

### 为什么有些文字没有翻译

当前版本处理普通网页中已经加载、可读取的文字，包括主文档和有访问权限的 HTTP/HTTPS iframe。

以下内容不在当前支持范围内：

- 图片、Canvas、SVG 中的文字和 OCR 识别。
- 浏览器内置 PDF 查看器、扫描 PDF。
- 浏览器内部页、扩展管理页、扩展商店页。
- 输入框、文本域、可编辑区域和代码块。
- 网站标记为 `translate="no"`、`.notranslate` 的区域，以及隐藏内容。
- 组件的 Shadow DOM 内部文字。

尚未滚动加载到页面中的内容，需要先滚动加载。插件会继续翻译新出现的文字，但不会自动滚动、展开折叠区域或点击“加载更多”。

### 为什么刷新后会重新翻译

原文、译文和缓存只保存在**当前页面的内存中**。刷新或关闭页面后会清空，再次翻译会重新请求 API。

### 如何更新插件并保留 Key

1. 下载新版插件安装包并解压。
2. 用新版文件覆盖原来加载的插件文件夹。
3. 在扩展管理页找到“页译”，点击 **重新加载**。
4. 刷新设置页和待翻译的网页。

继续使用原来的插件目录，可以保留该扩展已有的本机设置。

## 数据保存和访问权限

- Key、服务配置、阅读偏好和自动翻译网站名单仅保存在浏览器本机扩展存储中，不使用浏览器同步。
- 存储访问限制为扩展可信页面和后台，网页内容脚本收到的配置不包含 Key。
- 原文和译文不写入本机持久存储，只存在当前页面内存中。
- 网页文字直接发往你配置的 API。页译没有中转服务器和遥测，也不会记录 Key、请求原文或原始响应。
- 界面中的服务错误经过脱敏和长度限制。
- 要移除 Key，清空对应输入框并保存。卸载扩展会移除其本机设置。

扩展需要的权限及用途：

| 权限                     | 用途                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `storage`                | 保存本机设置                                                         |
| `activeTab`、`scripting` | 对当前网页执行操作，给安装前已打开的网页补充脚本                     |
| HTTP/HTTPS 网站访问      | 显示网页入口、按站点自动翻译、处理可访问的网页帧，以及连接配置的 API |

默认使用手动翻译。自动翻译只对你主动添加的网站生效。

## 从源码构建

本节供开发者使用。普通用户直接下载 Release 中的插件 ZIP 即可。

需要 Node.js 20 或以上版本。在项目根目录执行：

```powershell
npm ci
npm run build
```

构建完成后，将生成的 **`dist/`** 文件夹加载到浏览器。源码仓库不包含预构建的 `dist/` 和安装包，这些产物通过 Release 提供。

生成可分发的安装包：

```powershell
npm run package
```

当前版本的安装包会写入 `release/yeyi-translator-1.0.2.zip`。

### 运行检查和测试

```powershell
npx playwright install chromium
npm test
npm run check
npm run format:check
```

- `npm test`：运行连接错误、模型列表等快速回归测试，以及真实加载扩展的浏览器验收。
- `npm run check`：检查脚本语法、扩展入口、Manifest V3 的代码限制和测试数据隔离。
- `npm run format:check`：检查源码和文档的格式。

当前已通过 **6 项快速回归测试和 27 项浏览器验收场景**。API 测试使用独立的本地替身服务，没有使用真实 Key 验证各家服务的实际可用性或翻译质量。

浏览器验收使用 Playwright 配套的 Chromium 和独立的临时配置目录，不接触已有 Chrome / Edge 配置。截图和报告保存在 `test-results/`，不会进入安装包。[Playwright 扩展测试说明](https://playwright.dev/docs/chrome-extensions)

## 自定义 API 的兼容要求

以下内容供对接代理服务或本机服务时参考：

- 翻译接口兼容 `POST /chat/completions`，使用 Bearer Key、`messages`、`stream` 和 `response_format: {"type":"json_object"}`。
- 成功响应通过标准 `choices[].delta.content` 或 `choices[].message.content` 返回译文。支持 SSE 流式响应和完整 JSON 响应。
- 自动获取模型使用 `GET /models`，从响应的 `data` 数组读取模型 `id`，以及可选的展示名 `name`。
- Base URL 可以是 API 根路径、带 `/v1` 的根路径，或完整的 `/chat/completions` 端点。完整端点不会重复拼接；其他地址会追加 `/chat/completions`，不会自动增删 `/v1`。
- API 地址使用 HTTPS。本机 `http://localhost`、`http://127.0.0.1` 和 IPv6 回环地址可以使用 HTTP。
- 扩展最低要求为 Chromium 主版本 120，使用 Manifest V3。

官方接口参考：

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- [OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)
- [DeepSeek 首次 API 调用与模型名称](https://api-docs.deepseek.com/guides/codex)
- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)
- [DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)
